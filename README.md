# ميزان — لوحة حية لكشف التلاعب بالمزادات

موقع حي (dashboard) يرفع فيه المستخدم ملف CSV، ويشغّل السيرفر نموذج
Isolation Forest حقيقي (scikit-learn) + سلسلة تحقق SHA-256 على البيانات
فوراً ويعرض النتائج في المتصفح.

## الفكرة الأساسية

الدخول عبر إنفاذ وأبشر يثبت **مَن** هو المزايد، لكنه لا يثبت أنه **قادر**
على السداد. المشكلة العملية: مزايد غير قادر ماليًا يرسو عليه المزاد ثم لا
يكمل السداد، فتطول الإجراءات وتدخل القضاء ويُعاد طرح الأصل ويُباع بسعر أقل.

ميزان طبقة تقيس **القدرة على السداد قبل الترسية**، عبر:

1. **الملاءة المالية** — إيقاف خدمات قائم، قروض غير مسددة، تعثرات سابقة،
   وكفاية الضمان المقدَّم.
2. **السجل في المزادات** — فوز سابق دون إكمال السداد، وتنبيه خاص حين
   تتجاوز مزايدته الحالية المبلغ الذي عجز عن سداده سابقًا.
3. **مؤشران سلوكيان ثانويان** (الشذوذ الإحصائي وتكرار رفع السعر) — يُعرضان كسياق للمراجع البشري فقط.

هذا مؤشر دعم قرار لمراجع بشري، وليس حكمًا آليًا.

## أعمدة ملف CSV

**مطلوبة:** `auction_id`, `event_time`, `bidder_id`, `bid_amount`

**اختيارية** — التحليل لا يتوقف بغيابها، لكن العامل المبني عليها يُوسم
**«غير متوفر»** ولا يُحتسب صفرًا (غياب البيانة ليس دليل سلامة):

| العمود | المعنى | المحور |
|---|---|---|
| `has_service_suspension` | 0 أو 1 — إيقاف خدمات قائم | الملاءة المالية |
| `outstanding_loans` | قيمة القروض غير المسددة بالريال | الملاءة المالية |
| `prior_payment_defaults` | عدد التعثرات المالية السابقة | الملاءة المالية |
| `guarantee_amount` | قيمة الضمان/الكفالة المقدَّمة بالريال | الملاءة المالية |
| `prior_unpaid_wins` | مرات الفوز بمزاد سابق بلا سداد مكتمل | السجل في المزادات |
| `prior_unpaid_bid_amount` | قيمة المزايدة السابقة التي أخفق في إتمامها | السجل في المزادات |

مصدر هذه الحقول عمليًا هو الجهات الحكومية وسجل المزادات؛ في هذه النسخة
تصل عبر ملف CSV يرفعه المشرف.

## محاور المؤشر والأوزان

كل الأوزان في ثابت `WEIGHTS` أعلى `api/analyze.py` — تُضبط من مكان واحد.

| المحور | العامل | الوزن |
|---|---|---|
| **الملاءة المالية** | إيقاف خدمات قائم | 45 |
| | قروض غير مسددة مقارنةً بأعلى مزايدة | حتى 40 (الحد عند نسبة 50%) |
| | تعثرات مالية سابقة | 12.5 لكل تعثر (سقف 25) |
| | ضعف تغطية الضمان | حتى 25 |
| **السجل في المزادات** | فوز سابق بلا إكمال سداد | 20 لكل مرة (سقف 40) |
| | تجاوز مزايدته السابقة المتعثرة | 15 |
| مؤشرات سلوكية ثانوية | سلوك شاذ إحصائيًا | حتى 10 |
| | تكرار رفع السعر | 2.5 لكل مرة (سقف 5) |

**المؤشران السلوكيان مجموعهما 15 عمدًا** — أي أقل من عتبة «متوسط»
(40)، فلا يستطيع أيٌّ منهما ولا مجتمعين أن يرفعا تصنيف مزايد وحدهما. أُبقيت
لأنها سياق مفيد للمراجع البشري، لا سبب للمنع.

**أربعة عوامل تبلغ وحدها عتبة «متوسط» (40)** لأن كلًّا منها يستوجب مراجعة
بشرية بمعزل عن غيره: إيقاف الخدمات، وقروض تفوق نصف قيمة المزايدة، وفوزان
سابقان بلا سداد، وضمان ضعيف جدًا مع تعثرات.

**تنبيه تجاوز المزايدة المتعثرة:** حين تتجاوز مزايدة المزايد الحالية المبلغ
الذي عجز عن سداده في مزاد سابق، يُضاف عامل صريح بهذا الاسم ليتحقق المراجع
البشري قبل الترسية.

**تغطية الضمان** = الضمان المقدَّم ÷ أعلى مزايدة للمزايد، والمتوقع 10% فأكثر
(`ADEQUATE_GUARANTEE_RATIO`). العتبة 10% لأن الضمان نسبة من سعر الافتتاح
والمزايدة قد تتجاوزه؛ عتبة أعلى تَسِم كل المزايدين تقريبًا بضعف الملاءة.

## اكتمال البيانات

يُرجع الـ API حقل `field_sources` لكل عمود اختياري (`uploaded` أو
`unavailable`)، وتعرض اللوحة شارة **«تغطية البيانات ٪»** أعلى الجدول مع
قائمة العوامل الغائبة. العامل الذي تغيب بيانته يظهر «غير متوفر» بإطار
متقطّع بدل أن يُعرض صفرًا يوهم بالسلامة. ويُفرَّق بين «غير متوفر» (العمود
غائب) و«لا ينطبق» (العمود موجود ولا توجد واقعة سابقة).

**ما ليس في النظام بعد:** لا يوجد تكامل مباشر مع إنفاذ أو أبشر أو سمة —
كل البيانات تصل عبر ملف CSV يرفعه المشرف.

## هيكل المشروع

```
mizan-dashboard/
├── public/
│   ├── index.html            ← الواجهة (رفع الملف + الرسوم + الجداول)

│   └── assets/fonts/         ← ملفات خط ثمانية (woff2)

│   ├── analyze.py            ← التحليل: Isolation Forest + سلسلة SHA-256
│   └── explain.py            ← تفسير سبب المخاطرة عبر Claude (+ بديل محلي)
├── requirements.txt          ← مكتبات بايثون المطلوبة
├── vercel.json               ← إعدادات Vercel
├── sample_auctions.csv       ← ملف تجريبي صغير
├── auctions_full.csv         ← بيانات واقعية شاملة (832 حدثًا · 22 مزادًا · 55 مزايدًا)
├── auctions_required_only.csv ← نفس الأحداث بالأعمدة المطلوبة فقط (لعرض «غير متوفر»)
└── DATA.md                   ← دليل الحالات: أي مزايد يمثّل أي حالة
```

## النشر على Vercel

### الطريقة 1: عبر GitHub (موصى بها)

1. سوّي مستودع (repository) جديد على GitHub وارفع كل محتويات هذا المجلد فيه.
2. روح لـ https://vercel.com وسجّل دخول (تقدر تسجل بحساب GitHub مباشرة).
3. اضغط **Add New → Project**، واختر المستودع اللي رفعته.
4. اترك كل الإعدادات على الوضع الافتراضي واضغط **Deploy**.
5. بعد دقيقة أو دقيقتين، بيعطيك Vercel رابط مباشر (مثل `mizan-dashboard.vercel.app`).

### الطريقة 2: عبر Vercel CLI (من جهازك مباشرة، بدون GitHub)

```bash
npm install -g vercel
cd مسار-هذا-المجلد
vercel login
vercel --prod
```

بيسألك بضعة أسئلة (اسم المشروع، إلخ) — اقبل الإعدادات الافتراضية، وبينشر الموقع مباشرة ويعطيك الرابط.

## اختبار الموقع

بعد ما يفتح الرابط، ارفع ملف `sample_auctions.csv` الموجود بهذا المجلد
(أو ملف `auctions_week.csv` الأصلي عندك) لتشوف النتائج الحية.

**الأعمدة المطلوبة بأي ملف CSV يُرفع:**
`auction_id`, `event_time`, `bidder_id`, `bid_amount`

## ملاحظة مهمة

كل مرة يرفع فيها المستخدم ملف جديد، يُعاد تشغيل نموذج Isolation Forest
وسلسلة SHA-256 من الصفر على البيانات الجديدة — النتائج فعلية ومحسوبة
لحظياً، وليست نتائج ثابتة أو مفترضة مسبقاً.

## تسجيل دخول المسؤول

عند فتح الموقع لأول مرة، يُطلب تسجيل دخول قبل الوصول للوحة:

- اسم المستخدم: `admin`
- كلمة المرور: `mizan2026`

**مهم:** هذا تسجيل دخول بسيط من جهة المتصفح (مناسب لنسخة تجريبية/عرض).
لو الموقع سينتقل لبيئة إنتاج فعلية بمستخدمين حساسين، يفضّل استبداله بتحقق
حقيقي من جهة السيرفر بدل بيانات ثابتة بالكود. يمكن تغيير الاسم وكلمة
المرور من ملف `public/login.html` (المتغيرات `ADMIN_USER` و`ADMIN_PASS`).

## لوحة مؤشر مخاطرة المزايدين

فوق جدول الأحداث الفردية، توجد لوحة "مؤشر مخاطرة المزايدين" التي تجمّع
النتائج على مستوى كل مزايد (لا كل حدث)، مع تصنيف منخفض/متوسط/مرتفع،
فلترة حسب المستوى، فرز حسب أي عمود، والضغط على أي صف يفتح تفصيل العوامل
الأربعة التي بُني عليها المؤشر والإجراء الموصى به.

## اللغة

زر أعلى يمين الصفحة يبدّل الواجهة بالكامل بين العربية والإنجليزية
(بما فيها التقرير الأسبوعي القابل للطباعة)، ويُحفظ الاختيار للزيارة القادمة.

## قرار المسؤول على كل حدث مشتبه به

بكل صف بجدول الأحداث المشتبه بها فيه زرّين: **تأكيد تلاعب** و**إلغاء الشبهة**.
القرار يُحفظ محلياً بمتصفح المسؤول (localStorage) ويظهر أيضاً بتقرير
الإنشاء الأسبوعي. القرار مرتبط ببصمة (hash) كل حدث تحديداً، فما يتكرر
أو يختلط بين الأحداث.

## التقرير الأسبوعي

زر "📄 إنشاء التقرير الأسبوعي" أعلى الصفحة يفتح نافذة جديدة فيها تقرير
منسّق (الإحصائيات + جدول الأحداث المشتبه بها مع قرار المسؤول لكل حدث)
وتفتح تلقائياً نافذة الطباعة — تقدر تحفظه كـ PDF مباشرة من هناك
(اختر "Save as PDF" بدل الطابعة).

## الوضع الفاتح/الداكن

زر أعلى يمين الصفحة يبدّل بين الوضعين، والاختيار يُحفظ للزيارة القادمة.

## تفسير سبب المخاطرة بالذكاء الاصطناعي

بالضغط على أي مزايد في جدول المخاطرة تظهر تفاصيل العوامل، وفيها زر
**«تفسير سبب الخطر بالذكاء الاصطناعي»**. يرسل الزر أرقام هذا المزايد فقط إلى
`api/explain.py`، الذي يستدعي نموذج ذكاء اصطناعي ليكتب شرحًا مختصرًا بلغة
الواجهة: لماذا ارتفعت الدرجة، ووزن كل عامل بالنقاط، والإجراء المقترح.
التفسير يظهر داخل الصف ويُدرج أيضًا في التقرير الأسبوعي.

### المزوّدات المدعومة

| المتغيّر | المزوّد | النموذج الافتراضي |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude | `claude-opus-5` |
| `GEMINI_API_KEY` (أو `GOOGLE_API_KEY`) | Gemini | `gemini-3.8-flash` |

- يكفي ضبط **أحدهما**. إن ضُبط الاثنان يُستخدم Claude افتراضيًا.
- لإجبار مزوّد معيّن: `AI_PROVIDER` = `claude` أو `gemini`.
- لتغيير نموذج Gemini: `GEMINI_MODEL` (مثلًا `gemini-2.5-flash`).
- Gemini يُستدعى عبر REST مباشرة بلا أي مكتبة إضافية، والمفتاح يُرسل
  بترويسة `x-goog-api-key` لا في الرابط.

### تفعيله على Vercel

1. من لوحة المشروع في Vercel: **Settings → Environment Variables**.
2. أضف المتغيّر المناسب لمزوّدك: `ANTHROPIC_API_KEY` من
   [console.anthropic.com](https://console.anthropic.com)، أو `GEMINI_API_KEY`
   من [aistudio.google.com](https://aistudio.google.com/apikey) (اختر
   Production والبيئات الأخرى التي تريدها).
3. أعد النشر (Redeploy) ليقرأ المشروع المتغيّر الجديد.

**بدون أي مفتاح لا تتعطل اللوحة:** يُبنى تفسير احتياطي محليًا من نفس أوزان
المؤشر ويظهر موسومًا بـ «تفسير محلي»، فيبقى العرض التوضيحي شغّالًا دائمًا.
وينطبق الأمر نفسه لو فشل استدعاء المزوّد (مفتاح خاطئ، انقطاع، تجاوز حصة):
يسقط الرد تلقائيًا للتفسير المحلي مع بيان السبب في حقل `fallback_reason`.

المفتاح يبقى في متغيّرات بيئة السيرفر ولا يصل للمتصفح إطلاقًا. كذلك تُنظَّف
معرّفات المزايدين القادمة من ملف CSV وتُمرَّر للنموذج داخل وسم
`<bidder_data>` كبيانات لا كأوامر، حمايةً من محاولات حقن التعليمات عبر ملف
مرفوع.

## الخط

واجهة اللوحة وصفحة الدخول والتقرير المطبوع تستخدم **خط ثمانية**
(Thmanyah Sans للنصوص، وThmanyah Serif Display للعناوين). ملفات الخط بصيغة
woff2 داخل `public/assets/fonts/` وتُحمّل محليًا بلا أي اتصال خارجي.

## تحسينات الواجهة والتفاعل

كل المزايا السابقة باقية كما هي، وأضيف إليها:

- **مسار عمل مرئي** أعلى اللوحة (رفع الملف ← مراجعة المخاطرة ← اتخاذ القرار ←
  إصدار التقرير) يتقدّم تلقائيًا مع خطوات المستخدم.
- **سحب وإفلات** ملف CSV مباشرة على صندوق الرفع، مع عرض اسم الملف وحجمه
  وإمكانية إزالته والعودة للحالة الفارغة.
- **بطاقات مؤشرات بأيقونات وشرح**: مرّر المؤشر على علامة (i) بكل بطاقة ليظهر
  تعريف مختصر للمقياس بلغة الواجهة الحالية.
- **رسم بياني إضافي**: حلقة (doughnut) توزّع المزايدين على مستويات
  مرتفع/متوسط/منخفض بجانب مدرّج توزيع درجات الشذوذ، مع تلميحات تفاعلية.
- **بحث وفرز أوسع**: بحث برقم المزايد في جدول المخاطرة، وبحث برقم المزاد أو
  المزايد في جدول الأحداث، وفلترة الأحداث حسب القرار
  (الكل/قيد المراجعة/مؤكد التلاعب/ملغى)، مع عدّاد "س من ص" لكل جدول.
- **شريط مخاطرة مصغّر** بجانب كل درجة مخاطرة ليُقرأ المستوى بلمحة.
- **إشعارات (toast)** بدل رسائل المتصفح المنبثقة، ومؤشر تحميل متحرك أثناء
  تشغيل النموذج.
- **تبديل اللغة يعيد بناء الجداول والرسوم** بالكامل، فما تبقى أي نصوص بلغة
  سابقة بعد التبديل.
- **رسائل خطأ ثنائية اللغة** من الـ API (حقلا `error` و`error_en`).
- **تجاوب أفضل مع الجوال** وصفحة تسجيل دخول بنفس الهوية البصرية مع خيار
  إظهار/إخفاء كلمة المرور.
